## 2. 微服务划分

| 服务名称 | 职责 | 技术栈 | 依赖 |
|---------|------|--------|------|
| **gateway-service** | API网关、认证、限流 | Kong/Nginx + Lua | 无 |
| **auth-service** | 用户认证、授权、SSO | NestJS + JWT | PostgreSQL, Redis |
| **user-service** | 用户管理、角色管理 | NestJS + Prisma | PostgreSQL |
| **subscription-service** | 订阅管理、配额计费 | NestJS | PostgreSQL, Redis |
| **orchestrator-service** | 统一调度、Agent协调 | NestJS | Redis, Kafka |
| **data-collection-service** | 数据采集、交叉核验 | NestJS + Python | PostgreSQL, MongoDB, Redis |
| **smart-reach-service** | AI外呼、触达任务 | NestJS + Python | Kafka, Redis, 语音API |
| **content-service** | 内容生成、文案创作 | NestJS + LLM | Redis, MongoDB, 对象存储 |
| **crm-service** | 客户管理、生命周期 | NestJS | PostgreSQL, Redis, Elasticsearch |
| **compliance-service** | 合规审核、敏感词 | NestJS | PostgreSQL, Redis |
| **analytics-service** | 数据分析、报表 | NestJS + ClickHouse | ClickHouse, Redis |

## 3. 服务通信

### 3.1 同步通信 (gRPC)

```
auth-service ↔ user-service
user-service ↔ crm-service
orchestrator-service ↔ 各Agent服务
```

### 3.2 异步通信 (Kafka)

```
data-collection → smart-reach (新数据通知)
smart-reach → crm (意向更新)
content → notification (内容生成完成)
各服务 → analytics (事件上报)
```

### 3.3 事件驱动

```
用户注册 → 初始化CRM档案
触达完成 → 更新客户状态
内容发布 → 触达任务执行
违规检测 → 告警通知
```

## 5. 部署架构

### 5.1 环境配置

```
开发环境:
├── Local: Docker Compose (全部服务本地运行)
└── 资源: 16GB RAM, 4CPU

测试环境:
├── K8s Namespace: fangtan-test
├── 副本: 各服务2副本
└── 资源: 32GB RAM, 8CPU

预发布环境:
├── K8s Namespace: fangtan-staging
├── 副本: 各服务3副本
└── 资源: 64GB RAM, 16CPU

生产环境:
├── K8s Namespace: fangtan-prod
├── 副本: 各服务5-10副本
├── HPA自动扩缩容
└── 资源: 256GB RAM, 64CPU
```

## 6. 高可用设计

### 6.1 服务冗余
- 所有服务多副本部署
- 自动故障转移
- 健康检查和探针

### 6.2 数据冗余
- PostgreSQL主从复制
- MongoDB副本集
- Redis主从 + Sentinel
- Kafka多副本

### 6.3 容灾备份
- 每日数据库备份
- 增量备份
- 跨区域备份
- 定期恢复演练

## 7. 监控告警

### 7.1 监控指标
- 服务健康状态
- API响应时间
- 错误率
- 资源利用率
- 业务指标（触达量、转化率等）

### 7.2 告警规则
- API响应时间 > 500ms
- 错误率 > 1%
- CPU使用率 > 80%
- 内存使用率 > 80%
- 服务不健康
